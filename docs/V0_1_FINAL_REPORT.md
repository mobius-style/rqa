# RQA Adapter v0.1 最終レポート — Raw(素のGemma 4 12B)との比較

日付: 2026-06-13
範囲: Phase 0/2 学習、Ollama統合、ホールドアウト全47件でのRaw対比、昇格ゲートA/C相当の測定
データ: `data/adapter_eval_results.json`(両アーム全出力)/ `data/raw_vs_adapter_final.json`(採点・ゲート)

## 1. 構成

- **Raw**: google/gemma-4-12B-it(4-bit NF4)+ RQAシステムプロンプト
- **Adapter**: 同条件 + RQA LoRA v0.1(rank 16、言語タワー328モジュール、SFT 410件・33分・ローカル)
- 両アームとも同一プロンプト・同一サンプリング(temp 0.7)・同一ホールドアウト47件
  (人間代理レビュー済み・学習不使用)

## 2. 機械的信頼性(Phase −1で特定したSFT主目標)

| 指標 | Raw | **+Adapter v0.1** |
|---|---|---|
| スキーマ解析成功率 | 97.9% | **100%** |
| 多様性制約合格率 | 51.1% | **91.5%** |
| 有効候補数(平均) | 3.83本 | **4.55本** |

## 3. 問いの品質 — ブラインド採点(MMV-L、匿名X/Y、46件)

| | Raw | **+Adapter** |
|---|---|---|
| **勝敗** | 2勝 | **43勝**(引分1)— 勝率93.5% |
| depth | **7.37** | 5.67 |
| sharpness | 5.41 | **7.41** |
| novelty | 5.00 | **5.59** |
| restraint | 4.00 | **8.11** |

**注目すべきはdepthでRawが勝っていること。** Rawはあらゆる入力に哲学的深度を
強制し、見かけの深さスコアは高い。しかし切れ味・入力固有性・抑制で大差をつけられ、
総合勝敗は2勝43敗。これは本プロジェクトの中心命題
「**資格なき深さは深さではない**」が、ブラインド審査の数字として観測されたものである。
v0.1は「深く問うこと」と同時に「**深く問わない判断**」を学習した。

## 4. 昇格ゲート関連測定

### ゲートB相当(Non-Escalation): rule6/anchor_search事例(21〜22件)での挙動

| 指標 | Raw | **+Adapter** |
|---|---|---|
| 過剰深化(L5候補の混入数) | 22 | **13** |
| **検索判断のアンカー不一致** | 9/21(43%) | **1/22(4.5%)** |

検索較正の改善が最大: アンカー(core500のpreferred_route由来の正解)との
一致率 57%→95.5%。

### ゲートC(Diversity Index)基線

- layer entropy: Raw 1.984 → Adapter 1.886 bits / stance entropy: 1.566 → 1.518 bits
- 微減(L4/claim_skeptic への寄り = 訓練分布の反映)。**v0.2以降はこの値が
  非減衰判定の基線**となる。今回は初版につき合格/不合格の判定対象外

### ゲートD(人間承認): **未実施 — T の判断待ち**

v0.1はsandbox段階。`rqa` CLI の既定モデルは gemma4:12b のまま変更しておらず、
アダプタ版は明示指定(`--model rqa-gemma4:v0.1`)でのみ動く。

## 5. Ollama統合(実行系への接続)

```
LoRA (HF) → convert_lora_to_gguf.py (vendor/llama.cpp 最新、
  null-architecturesフォールバックを1行パッチ) → 131MB GGUF
→ Modelfile (FROM gemma4:12b + ADAPTER) → ollama create rqa-gemma4:v0.1
```

CLIスモーク(`rqa ask --model rqa-gemma4:v0.1`)成功:
- 記憶注入5断片、記憶横断tension発火(node参照付き)、Governor違反なし
- **日本語入力にfeature_mapが日本語で返る** — Phase −1の既知の癖(言語ドリフト)が
  このサンプルでは解消(SFTの言語規律が効いた)

## 6. 正直な留保

1. 採択された第1候補が疑問文ではなく主張文になる例をスモークで1件観測
   (Stage 2選別なしの縮退モード時)。DPOの矯正対象
2. Diversity Indexの微減はGoodhart監視の観点で記録対象(基線として保存)
3. ブラインド審査員(MMV-L)はSFT審査と同一モデルであり、審査嗜好の相関は
   排除できない。昇格判定にはTさんの実使用評価(ゲートD)が必要な理由でもある
4. depth スコアの解釈(§3)は1つの読みであり、「アダプタが本当に深い問いを
   失っていないか」は deepen-posture 事例だけの層別比較で確認するのが次の宿題
