# MOBIUS-RQA / BRSA 仕様 v0.3 差分 — 会話表面(Conversational Surface)

日付: 2026-06-13
基底: SPEC_v0_2.md(v0.2全文は有効。本差分はその上に重なる)
起点: ゲートD試用のオーナー所感(2026-06-13)
「いきなり問いに問いで返すのではなく、ジェマなりの答えを返して、
それに付随する形で問いが自然に加わるほうが会話の流れがスムーズになる」

## 1. 設計判断の訂正(v0.2の過剰回転)

v0.2は究極報酬「より深い問い」を**会話表面の形式**にまで持ち込み、
出力を問いのみとした。これは内部報酬と表面形式の混同であり、
製品レベルの過剰ask(リスク17.2-9)を自ら実装していた。

**訂正**: 究極報酬・ゲート・選別・蓄積はすべて不変。変わるのは配達方法のみ。

```txt
v0.2: 入力 → [反省ループ] → 問い(だけ)を返す
v0.3: 入力 → [即時] 自然な応答をストリーミング(回答資格の規律つき)
            → [並行] 反省ループ(サイドカー)
            → [合流] 選別閾値を超えた問いが 1本だけ 追伸として加わる
            → [沈黙] 閾値未達なら何も足さない(沈黙は失敗ではなく既定)
```

## 2. 二つのモード(製品形態の分離)

```txt
chat(会話モード, v0.3新設):
  - 応答ペルソナ: 自然・簡潔・ユーザー言語(Gemmaの軽妙さを保存)。
    回答資格の規律: 揮発性事実は as-of 付きで答える。拒否ではなくヘッジ
  - サイドカー: 反省1ラウンド固定(会話のテンポに3ラウンドは不適)
  - 問いの表面化は 1ターン最大1本、Evaluator採点が閾値以上の時のみ。
    縮退時(Stage 2不能)は表面化しない(無認証の問いで会話を遮らない)
  - /full で直前ターンの計器盤(11.2形式)を開示 — 内部思考の可視化
  - ラリー: ユーザーの返答が次ターンのサイドカー入力になる(2.1の
    認識更新ループの製品化)。全ターンが Question Graph に蓄積

ask / review(計器モード, 従来):
  - 計器盤フル出力・複数ラウンド・文書レビュー。--brief で問いのみ表示
```

## 3. 統治の追加 — 記憶参照の機械検証(ゲート強化)

v0.1実機で**記憶参照の捏造**を確認(注入0断片の状態で存在しないnodeを
引用。SFTの擬似記憶例の副作用)。対策:

```txt
Controller は出力の tensions_memory_cross を検査し、memory_ref が
「このターンに実際に注入した node ID」に含まれないものを出力前に破棄する。
破棄はテレメトリと計器盤に記録される(モデルの出所主張は信用しない)。
根治は v0.2 アダプタの DPO(記憶なし→空配列の負例)で行う。
```

## 4. 計算資源の資格(軽量パス)

挨拶・相槌・短小断片(入力重み=light)にはサイドカーを起動しない。
深化のコストは深化に値する入力にのみ払う — Answer Entitlement の計算資源版。

## 5. 実装対応(2026-06-13 実装済み)

| 仕様 | 実装 |
|---|---|
| 会話モード | `rqa/chat.py`(ChatSession / run_repl)、`rqa chat` |
| ストリーミング | `OllamaAdapter.stream_chat` |
| 沈黙規則 | `should_surface`(閾値30/40、縮退時None) |
| 軽量パス | `input_weight`(light/normal) |
| 記憶参照検証 | `governor.sanitize_memory_refs` + Controller統合 |
| briefビュー | `render_brief`、`ask --brief` |
| サイドカー1ラウンド | chat時 `max_reflection_depth=1` |
| 単発会話CLI | `rqa chat "..."`。通常目視は chat、`ask` は計器モード |
| chat/light停止 | 自己紹介・能力確認・軽い幸福/雑談入口は memory/sidecar/evaluator を起動しない |
| chat追伸閾値 | total 34/40 以上、かつ depth/sharpness/actionability の下限を満たす時だけ表面化 |
| ask/light高速化 | 追加フラグなしの `ask` でも light入力は会話応答へ短絡。計器強制は `ask --instrument` |
| 対象未指定ガード | `この仕様/文書を見て` 型で本文・ファイルなしなら graph 推測せず対象提示を求める |
| RGC応答段階器 | `rgc_route` で L0固定/確認、L1直接回答、L2短時間サイドカー、L3計器盤へ滑らかに昇格 |
| 二段出力 | L2/L3は2秒以内に短い暫定回答を出し、重い処理が固まってから本出力を返す |
| L3中間観測 | 計器実行中は約12秒ごとに未確定結論ではない進行観測を出す |
| L3内部RGC予算 | `quick/standard/full` で k・反省深度・記憶注入量を入力重みに応じて調整 |

追補(2026-06-13 Codex): 実使用目視で `bin/rqa ask` が会話用途に使われ、
計器盤フル出力が表面に出る問題を確認。`chat` と `ask/review` の表面を再分離し、
`rqa chat "..."` の単発会話、light入力の強化、chat追伸閾値の引き上げ、
actionability下限、node二重表示修正を追加した。

追補2(2026-06-13 Codex): ユーザー実機では習慣的に `bin/rqa ask "..."` が使われるため、
light入力に限り `ask` 側も会話応答へ短絡する。旧来の計器盤を light 入力で見たい場合は
`ask --instrument "..."` を使う。

追補3(2026-06-13 Codex): 実機ログで `こんにちは` がまだ計器へ落ちること、
`この仕様の前提を見て` が Question Graph の過去断片から対象を推測してしまうことを確認。
挨拶の fast path と対象未指定ガードを追加した。

追補4(2026-06-13 Codex): オン/オフ切替が激しすぎるため、RGCを会話表面の
応答段階器として実装した。`ask` の既定は L0固定/対象確認、L1直接回答、
L2直接回答+短時間サイドカー(6秒上限)、L3計器盤へ昇格する。`--instrument` は常にL3。

追補5(2026-06-13 Codex): ユーザー体感では初期待機2秒がメルクマールのため、
L2/L3に二段出力を追加した。L2は短い暫定回答を即時表示し、非ストリームで固めた
会話回答を返す。L2の裏サイドカーは6秒上限で、間に合わなければ無表示で閉じる。
L3は短い暫定回答を即時表示してから計器盤を出す。

追補6(2026-06-13 Codex): L3の長時間待機対策として中間観測を追加した。
計器実行が続く間、約12秒ごとに「主張/前提の分離」「候補選別」「境界/記憶参照確認」
の進行状態だけを表示する。未採点の問いや暫定結論は出さない。

追補7(2026-06-13 Codex): L3内部にもRGCを導入した。`quick` は k=3/depth=1/memory=2、
`standard` は k=4/depth=2/memory=4、`full` は k=6/depth=3/memory=8 とし、
短い計器入力まで最大予算を使わない。`review` と文書・監査・公開・論文・特許などの
重い入力は full に昇格する。CLIで `--k` や `--depth` が指定された場合はその指定を尊重する。
